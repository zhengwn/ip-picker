# IP Picker

面向 macOS 和 Windows 的 Cloudflare IPv4 优选工具。选择国家／地区，一键完成真实连接筛选、HTTPS 验证、下载测速和分区推荐，查看全部测试结果并筛选、收藏或复制 IP。界面采用 Vue 3 + TypeScript，桌面外壳采用 Tauri 2，测速核心使用 Rust 实现。

从源码启动桌面应用请参阅[开发环境](#开发环境)。

## 使用流程

1. 测速地区选项只保留香港、日本、新加坡、美国，按需选择。参数区不再设置每区保留数量或推荐偏好，直接在结果表筛选 IP。
2. 使用内置 Cloudflare 网段，或在高级设置中导入自己的 IPv4 / CIDR 列表。
3. 首次试用时，点「快速验证」；需要控制流量时，可主动开启下载预算。需要更大覆盖时，点「开始完整优选」，悬停测速按钮可查看预计耗时和下载正文流量，预算在高级设置中调整。普通测速和收藏复测均可在切换页面后查看当前进度、累计下载量并停止。
4. 精测结果表显示 IP、地区、延迟、下载速度和收藏按钮。地区同时显示 POP 代码，例如“美国 · LAX”。测速结束后可查看本轮各区统计和未取得结果的原因，也可在结果表展开单个 IP 的状态与原因。探测和下载样本继续随测量记录保存。
5. 在“测试结果”中按地区、POP、状态、IP / POP / 地区搜索、下载速率和 TCP 延迟筛选；POP 下拉列出本轮实际显示的代码（如 LAX、SJC），并随地区选择联动。各状态旁的数字会反映当前其他筛选条件。有完成下载的结果时，默认勾选“仅完成下载”，包含低于目标速率的结果。一轮结束后若没有完成下载，直接显示已取得的精测记录。默认按本次 TCP 稳定性延迟从低到高排列，也可按下载速度、初筛 TCP 或 IP 地址排序。下载完成开关和排序会记住你的选择，重新打开应用或开始新测试后继续沿用。点击 IP 旁的复制图标即可复制地址，也可直接收藏需要的 IP；收藏夹中仍可查看测试详情并复制 IP。

高级设置的“筛选与下载”中提供“限制下载流量预算”开关与预算金额，默认关闭；启用后的预设预算为 400 MiB。应用会保存你的开关选择，下次打开继续沿用。关闭预算时，每轮下载仍按设定轮数和时长执行。高级设置可调整候选数量、并发、超时、测试目标和复测次数。测速需要在 Tauri 桌面窗口内运行；浏览器预览用于界面开发。

首次进入时，界面突出「快速验证」，并同时说明两种模式的用途、参考耗时和流量；快速验证未找到结果不代表该地区没有可用 IP。

「快速验证」沿用所选地区、候选来源、测速目标和判定阈值，最多抽样 256 个地址，每区最多精测 4 个 IP，每个精测 IP 做 10 次 TCP 探测。下载复测为 2 轮，每轮正文读取最多 1 秒。快速验证与完整优选共用用户的预算设置，默认均不限制下载流量；主动启用预算后按所设额度执行，不另加 64 MiB 上限。本轮快照记录实际使用的参数和快速验证标记，历史中也保留该模式；旧记录未保存模式时显示“历史测速”，不推测为完整优选。高级设置调整下次测速参数，“本轮详情”保留本次实际参数；快速模式自动缩小参数不会触发设置已修改提示，普通测速继续使用之前的设置。

预计耗时按候选和精测名单满额计算，参考建连 150 ms、HTTPS 请求 500 ms。设置更短超时时采用该超时值，探测节奏和下载时长采用本轮配置。候选不足、提前淘汰、网络等待都会影响实际耗时。已知 Cloudflare 测速目标的正文量按请求大小和计划轮数估算，启用预算后受预算限制。其他目标关闭预算时，正文量取决于实际响应。

## 界面与窗口

默认桌面窗口为 1080 × 720，启动时居中，最小支持 760 × 620。采用紧凑桌面工具布局：顶部导航、横向地区与测试配置、占满剩余空间的结果表。两页首行共用操作轨道，“重新完整优选／手动添加 IP”使用相同位置的 120 × 32 按钮，“高级设置／新建收藏夹”也使用相同按钮区域。表格上方只保留单行结论和筛选栏；实际参数、设置差异、各阶段数量、地区统计和后续操作统一收进“本轮详情”浮层，展开时不挤压表格。切换“地区优选”与“收藏夹”时会保留各自的筛选、分类和滚动位置。结果表内部滚动，表头固定，地区、筛选和开始／停止操作不会随长列表滚走。“更多筛选”和测速进度详情使用浮层展开，支持 Esc、点击外部及切页时关闭，关闭后合理恢复焦点；仅在测速中、参数无效或测试失败时显示状态提示；闲置时不占额外高度。全局错误和短暂提示统一叠放，不推动按钮或表格。

界面使用靛蓝色强调选中状态，地区与 POP 以紧凑标签显示。下载速度旁的细条表示相对于本轮最高已测速率的比例；它不是链路利用率，未完成下载的样本使用灰色提示。浅色和深色模式使用同一布局密度。

高级设置使用独立抽屉，按“目标与来源、筛选与下载、稳定性”分组，支持方向键切换、Escape 关闭和关闭后焦点恢复；错误参数定位会自动打开对应分组。参数仍按原规则自动保存，无需点击“完成”才保存。搜索、地区、POP、排序、“更多筛选”和“仅完成下载”集中在同一筛选栏；清除筛选位于表格底栏，仅重置临时条件，保留下载完成开关和排序偏好。运行进度直接显示阶段序号、当前阶段进度、完整结果数量、耗时与下载量，探测明细和测试规则按需展开。收藏夹采用与测速结果一致的紧凑表格，每行显示 IP、分类、地区／POP、逐条历史 TCP 指标、下载速度及操作；点击 IP 左侧箭头展开完整备注与实测快照。列表直接显示最近测试时间和状态，复测差值与网络条件差异通过行内“变化”入口展开，普通行保持紧凑高度；工具栏和表头固定，仅表格区域滚动，小窗口下操作列固定在右侧。相同 IP 在不同分类中仍为独立记录。支持按 IP、POP、地区、备注或分类搜索，搜索不会缩小“一键复测本夹”的测试范围。收藏、分类维护和手动添加弹窗统一使用内部滚动，保持底部操作可见；提交失败的错误固定在操作栏上方，长错误可独立滚动，不会藏到备注区后面。

结果表的最低下载速度和最高 TCP 延迟筛选只匹配对应的完整有效测量，部分样本不会进入阈值筛选结果。运行时可用进度行的“查看记录”或空结果提示中的“查看已取得的记录”临时展示未完成下载的精测记录，不改变默认下载筛选偏好。“本轮详情”提供查看达标 IP、优先低延迟或下载速度的快捷入口，并按预算不足、稳定性失败或未发现地区提供对应设置入口。搜索、地区、POP、状态和阈值是临时条件，开始新一轮或重启后会清空；仅完成下载和排序偏好单独保存。高级设置的“恢复默认”保留所选地区；有效参数修改后自动保存，下轮测试生效，已有测量仍使用当轮配置解释。点击“完成”或关闭窗口时会等待待保存参数提交；保存失败会保留窗口并显示错误。无效草稿不会覆盖上次有效设置，也不会阻止关闭窗口。

## 自定义候选与测速目标

在高级设置的“目标与来源”中选择自定义列表，可粘贴内容或导入文本文件。只支持 IPv4 和 IPv4 CIDR，可用换行、空白、逗号或分号分隔，`#` 后为行内注释。例如：

```text
# 明确指定的候选 IP
104.16.1.1
104.17.1.1, 104.18.1.1
# 从网段抽样补充候选
104.19.0.0/24
```

列表最多 2 MiB（按 UTF-8 字节计）和 20,000 个 IP / 网段条目，候选上限 `maxCandidates` 为 1–10,000。粘贴或导入后即可检查列表，错误会标出对应字段及无效条目的行号。保存和开始测速也会执行同样的校验。明确 IP 按输入顺序去重并优先保留，超过候选上限时只取前面的地址。剩余名额从合并重叠范围后的 CIDR 抽样，跳过已保留的明确 IP。耗时和流量估算也按去重后的地址容量计算。抽样直接在网段范围内取地址。这些示例地址仅用于演示输入格式。

修改测速目标时，URL 和响应须满足以下条件：

- 使用 HTTPS 域名，可带端口，不能使用 IP 字面量或包含用户名、密码、URL 片段；证书须对目标域名有效。
- 同一目标域名和端口的 `/cdn-cgi/trace` 须返回匹配目标域名的 `h` 和有效的 `colo`。普通下载站即使能打开，也未必满足 POP 识别要求。请求不跟随重定向，非成功 HTTP 状态会被拒绝。
- 下载响应不能压缩，每轮须实际读取至少 64 KiB。开启流量预算时，还须返回预算内的明确 `Content-Length`；可使用支持 Range 的静态文件或默认测速地址。

## IP 收藏夹

点击 IP 旁的星标，将该 IP 和收藏时的测试情况保存到收藏夹。再次点击亮起的星标会打开收藏管理，可选择已有分类，用本轮测试更新快照或仅移除该分类中的收藏，也可另存到其他分类。同一个 IP 在不同分类中的快照和备注各自独立。默认提供“联通流量”“联通宽带”“移动流量”，可在右上角的收藏夹中新增、重命名或删除分类，也可移动收藏、编辑备注和移除 IP。

每条收藏独立保留测试时间、测试目标与配置、地区 / POP、TCP 探测明细与失败次数、HTTPS 验证和下载样本，以及本轮采集到的网络路径。普通分区优选、修改设置或重启应用不会覆盖已有快照。测试中、已停止或失败的观测也可以收藏，详情会保留当时的状态和完成程度。收藏夹与测试设置一起保存在本机；删除收藏夹会同时移除其中的收藏，不影响测试结果。

收藏夹内支持三种直接测速：点击“手动添加 IP”，输入单个 IPv4 后选择“仅收藏”或“收藏并测速”；点击某条收藏的“重新测速”；或选中一个收藏夹后点击“一键复测本夹”，测试其中全部 IP。这些操作使用当前测试参数与本轮预算设置，直接测试指定地址，不经过候选抽样、地区筛选、每区 20 个入围或前 10 名下载限制。仍遵守累计 2 次连接失败淘汰及完整验证规则，开启预算限制且预算不足时明确保留未完成状态；关闭后不受下载数据量限制。

收藏复测与普通分区优选共用测试资源，同一时间只运行一轮，可随时停止。测速期间仍可仅保存 IP、编辑备注、新建或重命名收藏夹；移动、删除和启动新测试等待当前测试结束。仅收藏已有 IP 只更新备注，保留实测快照。成功收藏后会记住上次选择的收藏夹；该偏好保存在本机 WebView，收藏夹被删除时回退到可用分类。已有收藏在复测进行中保留原快照，结束后更新对应 IP 的测试记录；失败结果也会如实保存。停止或关闭应用时，尚未开始的已有 IP 保留原记录。收藏时间、分类和备注保持不变，最新测试时间在列表直接显示；手动添加的 IP 即使测速失败也保留在收藏夹。收藏复测记录与最近一次分区优选分开保存。最近一次复测同时保存精简的前次测量摘要，可通过“仅看变化”筛选所选收藏夹中发生变化的记录；点击行内“变化”可看完整差值及对比时间。参数、网络接口或机房不同会单独提示，部分样本不会与完整结果混作有效差值；两次观测的差值不代表长期趋势。

收藏库的每次成功提交都会保存递增版本号，事件、读取和操作响应使用同一版本顺序。界面忽略迟到的旧收藏快照，避免旧 POP、测试结果或备注覆盖较新的记录；写入失败不会推进版本。旧收藏文件无需手动迁移。

批量复测的完整目标列表只保存在该次任务中，每条收藏快照的自定义来源仅记录当前 IP，避免收藏数量增加时重复保存整夹列表。启动收藏复测时，有效的当前设置会一并保存；任务生成的自定义来源不会覆盖用户设置。

收藏夹顶部保留搜索、新建和手动添加；分类、变化筛选、整夹复测及“更多”共用一行。已结束的复测记录、下次复测参数与分类管理收进“更多”浮层，展开时不挤压列表。进行中的复测仍常驻显示阶段、进度、累计下载量与停止按钮。

## 测速历史

顶部的「测速历史」保留最近 10 轮已结束的地区优选和收藏复测，包括保留了观测数据的已停止或失败任务。打开一轮后默认查看精测记录，也可以切换到全部候选，并按本轮 IP、POP 和状态筛选。输入完整 IPv4 地址，或从收藏行打开「对比历史」，即可查看该 IP 在各轮的 TCP 探测次数、失败次数、测满后的 P95 和下载结果。历史随应用数据保存在本机，升级后可查看旧版本保存的最近一轮地区优选和最近一次收藏复测。

对比同一台 4G 路由器的有线和 Wi‑Fi 时，可用相同参数对同一个收藏 IP 各复测一次，再在「测速历史」中查看对比。对比表显示各轮测速目标、探测和下载配置，并标出不同项。旧记录的「TCP 初筛」会显示单次延迟筛选的开启状态和当时的门槛。路由接口旁会显示采样 IP，便于确认该接口观测是否对应正在对比的地址。

## 测速与推荐

测速依次进行候选抽样、TCP 连通性筛选、POP 识别、全部入围候选的 TCP 稳定性复测，再从各地区选出前 10 名进行服务可用性验证和下载复测。连通性主指标采用 TCP 建连耗时；HTTPS 用于识别 POP、检查目标服务与 TLS 证书，相关验证记录随测速结果保存，并可在收藏详情中查看。连接指定 IP 时保留目标域名的 HTTP Host 与 TLS SNI，并验证证书；不会通过关闭证书校验来把失败连接算作成功。

**连通性初筛与质量筛选分开。** 初筛只检查 TCP 能否在 `connectTimeoutMs` 内连接成功；成功连接即使耗时超过 200 ms，也会进入 POP 识别。先记录实际发现的国家／地区，再确定各区入围名单并完成连续 TCP 稳定性测试。所有入围候选的稳定性测试结束后，才开始入选候选的服务验证与下载测速。初筛单次耗时只作记录与候选排序依据，不再用于一票否决。

**稳定性默认要求 100 次 TCP 探测的 P95 ≤ 230 ms，连接失败率 ≤ 1%。** 等于上限允许通过。`maxTcpMs` 只用于稳定性复测的所选延迟指标，与连接最长等待时间分开配置。峰值及单次超限数量仍保留展示。`stabilityLatencyMetric` 可选 `p95`、`average` 或 `max`；选择 P95 时不会因一个峰值超过 230 ms 就淘汰。历史记录保留当时是否使用单次延迟初筛及原判定指标，新规则不改写历史结果。

**除累计 2 次连接失败的候选外，全部入围候选均完成 100 次 TCP 探测。** 每次建立独立连接，同一 IP 串行执行，候选之间最多并行 4 个。默认启动间隔为 200 ms，等待连接使用 `connectTimeoutMs`；慢连接不会触发重叠或追赶式探测。合格候选约需 20 秒起，连接较慢时可能更久。对通过初筛与 POP 识别、进入各区入围名单的全部候选执行。

**累计 2 次连接失败立即淘汰。** 这里指整个候选测试过程中累计失败 2 次，无须连续失败，也不随 `maxStabilityFailurePercent` 调整。达到第 2 次失败便停止该 IP 的后续探测。其余候选完成全部探测，不因暂时的平均值、P95、最大值或慢样本数量提前结束；测满后才按配置的延迟指标和失败率上限判定。提前淘汰保留真实次数与原因，标记 `earlyRejection`，不会伪造成完成 100 次，也不能推荐。用户取消与提前淘汰分开记录。

服务复测在首次请求失败或接入地区漂移后立即结束。运行中展示累计已处理、待测和本批范围。已经完成并通过完整测速流程的 IP 显示为「测速完成 · 待汇总」，也可按该状态筛选。整轮结束后，表格按最终判定显示结果，清除「待汇总」筛选。

停止测试时，已经完成的 HTTPS 验证和下载样本会保留，正在等待的请求不计为失败。自定义下载目标缺少 `CF-Ray` 时，下载后的 POP 复核若被取消，会明确保留“复核未完成”，该样本不会据此被判为完整测速通过。

配置 `stabilityAttempts`（默认 100）、`stabilityIntervalMs`（默认 200）和 `maxStabilityFailurePercent`（默认 1）控制次数、间隔与测满后的连接失败率上限。累计 2 次失败始终直接淘汰；少于 2 次失败的候选测满后，还须满足所设失败率和延迟指标上限。未完成复测或没有成功连接的候选不参与新推荐。取消时保留实际完成次数，尚未执行或取消中的连接不补算成失败。旧记录没有这一测试时明确显示未测试。

TCP 稳定性详情展示成功数、连接失败率、平均值、中位数、最小值、最大值和 P95。平均值和中位数取自已取得的成功探测。失败率按失败数除以实际完成次数计算。P95 采用成功延迟排序后的最近秩（第 `ceil(0.95 × 成功数)` 个）。没有相应样本时显示未取得数据，不伪造 0 ms。这里的 TCP 连接失败率不是 ICMP 丢包率。

地区来自目标域名 `/cdn-cgi/trace` 返回的 `colo`，结合内置 POP 地点表映射。未收录的 POP 记为未知，不按 IP 归属地猜测。`loc` 是访客地区，不用于判断机房。Cloudflare 的[官方排障说明](https://developers.cloudflare.com/support/troubleshooting/general-troubleshooting/gathering-information-for-troubleshooting-sites/)介绍了 `colo` 的含义。

下载名单按完整稳定性测量择优确定，入选名单全部执行服务校验与逐个下载测速。结果表默认按选定的 TCP 稳定性延迟从低到高排列，用户可按实际下载速度、延迟、地区或状态筛选；不再由每区保留数量和推荐偏好决定界面选择。旧推荐参数仅为记录和接口兼容保留，新界面不设置最低推荐速率门槛。验证成功次数反映本轮请求结果，不等同于 ICMP 丢包率或长期可用率。

**测量结果完整保留。** 桌面新测试不使用推荐速度门槛，最低下载速度由结果表筛选决定。历史记录仍保留当时的低于目标等原因，可以查看、收藏或复制。“测试结果”默认只展示实际进行过精测的候选，包括完整测速达标、低于速率目标、稳定性未达标、提前淘汰、未入选下载和精测未完成的记录。仅做初筛、未入围或尚未实际开始精测的条目通过本轮统计和原因汇总排查。支持地区与 POP 下拉、状态筛选、IP / POP / 地区搜索、最低下载速率和最高 TCP 延迟筛选；每页 50 条，全部精测结果均可查询。未取得的指标显示为“—”，未完成探测不算作失败。文件导出功能已移除。

结果页默认展示精测 IP 和每条记录的测试结论。初筛阶段即出现 TCP 异常的 IP，可从初筛统计旁的「查看初筛异常」进入，支持按 IP 搜索。展开行可查看成功样本的延迟范围、超限次数和按顺序记录的探测。新测速会记录连接超时、系统连接错误及失败前的实际等待时间。收藏详情和测速历史中的「TCP 明细」也会显示这些观测。提前淘汰的 IP 仍可查看已取得的样本，最终 P95 在测满后展示。旧记录中缺失的失败等待时间显示为「未记录」。

第一版使用 HTTP/1.1，每次 HTTPS 测量建立独立连接，不复用连接池。指标定义如下：

- **TCP 连接（ms）**记录建立 TCP 连接的耗时。结果中的 `tcpMs` 保留初筛耗时。主表默认显示完整稳定性测试的所选判据（默认 P95）。按复测延迟排序时，切换显示指标会同步切换排序，选择对应延迟排序也会更新列指标；按下载速度、初筛或 IP 排序时保留原排序。缺少完整指标时可显示带标签的样本峰值或初筛耗时，无样本时显示“—”。按判定延迟排序或筛选时使用完整指标，初筛耗时可单独排序。
- **HTTPS 冷连接首响（ms）**：从发起请求到收到响应头的耗时，包含 TCP 建连、TLS 握手和等待响应；展示成功验证样本的中位数，不能与 ping 延迟直接比较。
- **HTTPS 波动（ms）**：本轮成功验证样本的最大耗时减最小耗时，不是标准差，也不是网络层抖动测量。
- **下载速率（Mbps）**：`读取的下载响应体字节数 × 8 ÷ 请求总耗时秒数 ÷ 1,000,000`。总耗时从发起请求计起，包含 TCP 建连、TLS 握手和首响等待；多轮结果取中位数。这是单请求的有效吞吐，不代表链路最大带宽，与复用连接或并行多连接测速的数值可能不同。

**内置网段默认覆盖每个 `/24`，每个子网随机抽取 1 个 IP。** 这采用 CloudflareSpeedTest 的默认覆盖方式；按内置的 15 条 Cloudflare 官方 IPv4 网段，共抽取 **5,956 个 IP**，并非逐个遍历网段内所有地址。每轮重新随机选取末段地址。高级设置仍可调整候选上限：小于 5,956 时只覆盖部分 `/24`；高于该值时先覆盖全部 `/24`，再增加同子网内的不同地址。使用旧版内置默认值 1,024 的当前设置会一次性更新为 5,956，自定义列表和历史测速记录保持原样。

**抽样候选不等于完整实测结果。** 正常完成一轮时，所有抽样地址都会经过 TCP 连通性初筛，所有 TCP 连通地址都会尝试识别 POP；连接失败或无法识别的也会保留相应状态。完成地区识别后，各地区严格按初筛 TCP 延迟从低到高排序，默认只保留 **前 20 个入围精测**，不足 20 个则全部保留。相同 TCP 延迟再按 HTTPS 耗时与 IP 排序，不会因为子网不同而让较慢的地址挤掉更快的地址。界面分别显示真实已识别总数、入围数与未入围数；未入围仅表示未安排精测，不表示不可用。

默认采用 **稳定性全部测完，再选每区前 10 名测速**：先完成各区入围的最多 20 个候选的稳定性测试，累计 2 次连接失败的直接淘汰。全部稳定性测试结束后，各区从稳定性达标候选中依次按连接失败率、所选 TCP 延迟指标、HTTPS 耗时、HTTPS 首响波动与 IP 排序，仅选 **前 10 个** 进入重复服务验证与逐个下载测速；不足 10 个则全部选择。入选名单会全部测试，也不因验证失败补入第 11 名。开启预算限制且预算不足，或用户停止时，保留已有观测。稳定性完成但未进入前 10 名的候选明确显示“未入选下载”，不会误报为下载未完成，也不会作为首选、备选或“验证通过”结果。

`regionalCandidateLimit` 默认为 20，控制每区稳定性入围数量；初筛单次延迟只用于这一排名，正式准入仍以连续 TCP 稳定性判据为准。`precisionMode` 默认 `adaptive`，使用各区入围上限；显式选择 `limited` 时，实际入围上限取 `regionalCandidateLimit` 与手动 `candidatesPerRegion` 的较小值。新测试记录 `stabilityFirst: true`，历史记录保留原流程与当时的入围规则，不补写成新策略。旧版本当前设置若仍使用默认 50 个入围，会一次性迁移为 20；其他自定义上限与历史结果保持原值。下载流量预算默认关闭（`downloadBudgetEnabled: false`）；启用后的预设金额为 400 MiB，由所有入选的下载候选共用。已保存的开启或关闭选择会继续沿用，历史测速记录缺少该字段时仍按当时的预算限制处理。

所得结果是本次候选和预算内的相对优选，不代表 Cloudflare 全网的最优 IP。网络环境、目标域名和测试时间都会影响结果。默认测试目标为 `speed.cloudflare.com`，完整实测通过只表示这个目标在本轮测量中通过检查，不能保证替换到小火箭等客户端的其他节点后仍能代理；实际节点的域名、TLS/SNI、端口和传输方式需要另外验证。

## 地区与网络路径

选择某个国家／地区表示寻找当前网络能测到该地区响应的候选，不能强制 Cloudflare 把请求送往指定地区。同一个 IP 在不同时间、网络或目标域名下可能由不同 POP 响应；Cloudflare 的 [Anycast 路由说明](https://developers.cloudflare.com/support/troubleshooting/general-troubleshooting/geographic-traffic-routing/)解释了这一限制。应用会区分未发现候选、候选不足和未达标等状态。

测速客户端主动禁用常规 HTTP 系统／环境代理，使用直接连接；TUN、VPN、透明代理、路由器和运营商路由仍会影响实际路径，应用无法据此证明流量完全没有经过代理。切换网络后应重新测速。

macOS 和 Windows 在每轮测试开始时读取首个候选 IP 的系统路由接口，并保存采样地址、采样时间和可识别的接口类型。这是单个目的地址的路由样本。只复测一个 IP 时，采样地址就是被复测的 IP。旧记录使用当时已保存的数据，未成功采集的记录显示「未记录」。

下载阶段使用单独的响应头超时和正文读取时长。开启预算后，按每个 IP 所需轮数预留最低样本量，再在获配的地区之间轮换。界面统计应用实际读取的响应正文，运营商计费流量还可能包含 TCP / TLS / HTTP 开销、系统缓冲和重传。TCP 筛选和 HTTPS 验证也会产生少量流量。

应用使用普通 TCP / HTTPS，不发送原始 ICMP 报文，也不修改 hosts、DNS 或系统代理。日常测速无需管理员权限。

## 本地数据与备份

应用标识为 `com.ippicker.desktop`。`state.json` 保存测试设置、收藏库、当前或最近一次地区优选、当前或最近一次收藏复测，以及较早历史的引用。较早的测速记录按轮保存在同一应用数据目录下的 `state.history/` 中。

| 系统 | 默认应用数据目录 |
| --- | --- |
| macOS | `~/Library/Application Support/com.ippicker.desktop/` |
| Windows | `%APPDATA%\com.ippicker.desktop\` |

分区优选页显示当前或最近一轮，较早的结果可在「测速历史」查看。超过历史保留上限时移除最早的记录，收藏快照独立保存。旧版单文件状态仍可读取。归档文件缺失时，应用会提示并继续加载主状态中的设置、收藏和最近测量。

关闭窗口或在 macOS 上从应用菜单退出（⌘Q）时，应用会先保存有效的待提交设置，再等待当前任务停止并保存观测。保存失败时，窗口会保留并显示错误，可修复后重试。运行中有新观测时，检查点按 5 秒间隔更新。即使下一次探测或下载仍在等待，应用也会按时补写已取得的最新观测。异常退出后，可从最后一次成功保存的检查点恢复，未结束的一轮会标记为已停止。

同一数据目录只允许一个应用进程持有，避免多个实例互相覆盖收藏和设置。目录中的 `instance.lock` 由操作系统管理，进程退出后自动释放锁，无需删除锁文件。

备份时先退出应用，再复制 `state.json` 和 `state.history/`（如有）。恢复时同样先退出，将同一备份中的文件和目录放回原处后重新启动。旧版单文件备份只需恢复 `state.json`。需要重置设置、收藏和测试记录时，可在退出后将文件和历史目录一并改名留存，重启会使用默认状态。

若启动时本地设置无法解析，应用会先将原始内容保存为同目录下唯一的 `state.json.recovery-*.bak` 文件，再显示备份路径并使用默认状态；关闭窗口或后续保存不会覆盖该备份。原文件读取失败或无法完成备份时会停止启动，保留原文件。可在退出应用后检查备份中的 JSON 格式或目录权限，修复后按上述恢复流程放回 `state.json`。

“仅完成下载”和排序偏好保存在 WebView 的 `localStorage`（键为 `ip-picker.result-preferences`），不包含在 `state.json` 备份内。浏览器界面预览也有自己的偏好存储，不会读取桌面的收藏或测试记录。

## 小规模网络诊断

命令行诊断入口调用与桌面相同的 Rust 测速核心，不写入桌面设置或测试历史。必须显式提供 JSON 配置文件；不带参数只显示用法并退出，不会启动默认网段扫描。配置字段使用 camelCase，与 [Rust `ScanConfig`](src-tauri/src/model.rs) 一致，省略字段采用其默认值。Rust 保留的推荐默认值与桌面有差异，例如 `ipsPerRegion` 为 3、`minDownloadMbps` 为 20；下面显式设为 1 和 0，使结果不受最低推荐速率门槛限制。

将下面内容保存为 `scan-config.json`。它只对列出的 4 个候选 IP 做初筛；`limited` 模式配合 `candidatesPerRegion: 1`，使每个所选地区最多 1 个候选进入精测，不保证 4 个地址都进入下载。下载正文总预算为 8 MiB，每轮正文读取最多 1 秒，共 2 轮，HTTPS 验证 2 次。地区列表与桌面提供的香港、日本、新加坡、美国一致，实际可能只发现其中少数地区。这些 IP 只是测试输入，并非预先推荐的结果。

```json
{
  "regions": ["HK", "JP", "SG", "US"],
  "source": "custom",
  "customIps": "104.16.1.1\n104.17.1.1\n104.18.1.1\n104.19.1.1",
  "maxCandidates": 4,
  "maxTcpMs": 230,
  "tcpLatencyScreening": false,
  "stabilityFirst": true,
  "stabilityAttempts": 100,
  "stabilityIntervalMs": 200,
  "maxStabilityFailurePercent": 1,
  "stabilityLatencyMetric": "p95",
  "tcpConcurrency": 4,
  "ipsPerRegion": 1,
  "preference": "daily",
  "minDownloadMbps": 0,
  "candidatesPerRegion": 1,
```
